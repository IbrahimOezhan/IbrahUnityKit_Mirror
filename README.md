<h1 id="ibrahunitykit">IbrahUnityKit<a class="anchor" href="#ibrahunitykit"><i class="fas fa-link"></i></a></h1>
<p>Source Code: <a href="https://gitlab.com/ibrahim_oezhan/IbrahUnityKit">Gitlab</a></p>
<h3 id="dependencies">Dependencies<a class="anchor" href="#dependencies"><i class="fas fa-link"></i></a></h3>
<ul>
<li><span style="color:red">Odin Inspector/Odin Validator: Not included! </span></li>
</ul>
<p>Unfortunately the Toolkit relies on Odin for specific Inspector related Attributes. I personally refuse to "vibe code" replacements for them as I don't want to have native replacements unless I myself understand them and preferably written them. This is why the code in the toolkit will not compile unless you have Odin Inspector as well as Odin Validator in your project. If you are capable and manage to code your own replacements or you know of existing, free, human-written libraries/plugins that could be used feel free to create a merge-request with the changes</p>
<ul>
<li>uLayout</li>
</ul>
<p>The toolkit uses uLayout to compliment the UI System. As its open source and the license allows it, it is included as a git submodule in the project.</p>
<h3 id="structure-sub-systems">Structure/ Sub Systems<a class="anchor" href="#structure-sub-systems"><i class="fas fa-link"></i></a></h3>
<p>Its composed of many different components and subsystems for doing different things. The components are structured in layers where each component can only use components from the layer below it.</p>
<p>The systems it contains are:</p>
<ul>
<li>Settings</li>
<li>Saving</li>
<li>User Interface</li>
<li>Interaction</li>
<li>Localization</li>
<li>Dialogue</li>
<li>Utilities</li>
<li>Debugging</li>
<li>Unlockables (with Achievements as Specialization)</li>
<li>Player Controller (Based on the Character Controller)</li>
</ul>
<h3 id="installation">Installation<a class="anchor" href="#installation"><i class="fas fa-link"></i></a></h3>
<h5 id="openupm">OpenUPM<a class="anchor" href="#openupm"><i class="fas fa-link"></i></a></h5>
<h5 id="second-option-upm-git-url">Second Option: UPM Git URL<a class="anchor" href="#second-option-upm-git-url"><i class="fas fa-link"></i></a></h5>
<h5 id="third-option-git-clone">Third Option: Git Clone<a class="anchor" href="#third-option-git-clone"><i class="fas fa-link"></i></a></h5>
<p>Simply clone the repository and put it into your project or add it as a submodule</p>
<h3 id="history">History<a class="anchor" href="#history"><i class="fas fa-link"></i></a></h3>
<p>IbrahUnityKit is  a toolkit for Unity that I have been working on for a long time now as I have been building my games.
The first version where similar already long refactored code system was implemented was actually <a href="https://ibrahim-oezhan.itch.io/my-uncles-story">My Uncles Story</a>. Back then I made a terrible Interaction System and some other code that I then thought I could reuse for my next projects. And so I did and with each project I improved it until its now in this state.</p>
<h3 id="ai-usage-disclosure">AI Usage Disclosure<a class="anchor" href="#ai-usage-disclosure"><i class="fas fa-link"></i></a></h3>
<p>AI is used in an Assisting way, instead of what many call "vibe coding". I write the entire code and I never copy paste code from an output to the codebase. I have set the instructions so that if I ask about something programming related I let AI only answer in conceptual terms by hand but AI is used for the following things:</p>
<ul>
<li>When I forget the name of a method that does X,Y,Z I ask AI to remind me</li>
<li>When I can't find the issue in my code I use AI as a help for debugging although the instructions are set in a way where it only gradually gives more revealing hints and starts with very simple ones first so it doesn't spoil the answer and I can find it out myself</li>
<li>AI is also used to discuss design decisions and the pros and cons if I don't feel I know if option A or B is the right one</li>
</ul>
